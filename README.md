# 🐾 PawBeauty — 반려동물 미용 예약

우리 아이의 특별한 하루를 위한 반려동물 미용 예약 반응형 웹앱입니다.
정부지원사업 / IR / 포트폴리오 시연을 목적으로, 접속 즉시 **실제로 운영 중인 서비스처럼** 예약의 처음부터
끝까지를 체험할 수 있게 만들었습니다. — 기획·디자인·개발 [미래에이아이랩](https://miraeailab.com/)

```
예약   홈(아이별 상태) → 반려동물 → 서비스 → 미용실(상세 비교) → 미용사 → 날짜/시간 → 요청사항·쿠폰 → 확정
이후   예약 확정 → 방문 전 안내 → 방문 당일 → 이용 완료 → 후기 → 다음 미용 추천일 → 같은 조건으로 재예약
       (방문 전날까지 일정 변경·취소 · 캘린더 추가 · 길찾기)
```

## 빠르게 시작하기

```bash
npm install
npm run dev          # http://localhost:3000 — 환경변수 없이 바로 동작 (샘플 데이터 자동 시드)
```

| 명령 | 내용 |
| --- | --- |
| `npm run check` | lint + typecheck + 단위 테스트 (커밋 전 빠른 확인) |
| `npm test` | 단위 테스트 (Vitest) — 예약 규칙·시간 슬롯·가격·저장 데이터 검증 |
| `npm run build && npm run test:e2e` | E2E 테스트 (Playwright) — 모바일·데스크톱 실제 사용 흐름, axe 접근성 검사, 반응형 |
| `npm run format` | Prettier 정리 (`format:check`는 CI에서 사용) |

> 브라우저가 미리 설치된 환경이라면 `PW_CHROMIUM_PATH=/path/to/chromium npm run test:e2e` 로 실행 파일을 지정할 수 있습니다.
> 처음이라면 `npx playwright install chromium` 을 먼저 실행하세요.

GitHub Actions(`.github/workflows/ci.yml`)가 PR마다 포맷 → lint → 타입 → 단위 → 빌드 → E2E 를 순서대로 돌립니다.

## 기술 스택

- **Next.js 15** (App Router) · **React 19** · **TypeScript** (strict)
- **Tailwind CSS 3** (디자인 토큰은 `tailwind.config.ts`) · **Lucide** 아이콘 · Pretendard 가변 폰트
- 데이터: localStorage 기반 데모 데이터 레이어 — Supabase 전환을 전제로 같은 테이블 구조(`supabase/schema.sql`)
- 테스트: Vitest(단위) · Playwright + @axe-core/playwright(E2E·접근성)

## 설계에서 신경 쓴 점

**예약 무결성 — "화면이 막아주길" 기대하지 않는다**
- 진행 가능한 단계는 "선택했는가"가 아니라 **선택값끼리 맞는가**로 계산합니다(`getMaxStep`).
  주소창에서 `?step=5`로 건너뛰거나, 새로고침·뒤로가기로 값이 어긋나도 맞는 단계로 돌아갑니다.
- 고양이 전용 서비스·고양이 전문 미용실은 강아지에게 선택되지 않고, 아이를 바꾸면 맞지 않는 선택만 풀립니다.
- 시간 슬롯은 지난 시간, 같은 미용사의 기존 예약, **같은 아이의 다른 예약과 미용 시간이 겹치는 구간**(소요 시간 기준 구간 겹침)을 막습니다.
- 시간은 **매장별 영업시간·점심시간·정기 휴무**와 당일 예약 마감(1시간 전)을 따릅니다. 휴무일은 달력에서 고를 수 없습니다.
- 확정 직전에 슬롯을 한 번 더 검증하고, 제출 잠금으로 연타해도 예약은 한 건만 생깁니다.
- 1회용 쿠폰은 취소되지 않은 예약에 쓰이면 다시 고를 수 없고, 그 예약을 취소하면 돌아옵니다. 첫 방문 쿠폰은 처음 가는 미용실에서만.
- 일정 변경은 자기 자신을 뺀 나머지 예약 기준으로 다시 검증하고, 방문 당일·지난 예약은 변경·취소할 수 없습니다.
- 예정된 예약이 있는 아이는 삭제할 수 없고, 삭제된 아이로 고르던 예약 선택값은 처음부터 다시 고르게 합니다.
- 취소·후기는 화면이 들고 있던 객체가 아니라 **저장소의 최신 상태**로 판단합니다(다른 탭에서 먼저 처리한 경우 대비).

**디자인 방향 — 사진이 이끄는 화면과 기능이 이끄는 화면을 나눈다**
- 고르는 화면(홈·미용실 상세)은 매장 인테리어·아이 사진이 주인공: 예약 카드는 매장 사진 위에 단계·D-day를,
  아이는 사진 타일로, 미용실 상세는 화면 끝까지 닿는 사진 위로 정보 시트가 겹쳐 올라온다.
- 실행 화면(예약 단계·확인·내역)은 기능 중심: 한 손으로 누르는 하단 고정 버튼, 그룹형 선택 목록, 영수증형 확인.
- 이모지 아이콘 대신 같은 굵기의 라인 아이콘 + 톤 타일(`ServiceIcon`), 사진 없는 미용사는 모노그램 아바타.
- 굵기는 제목 bold / 본문 regular로 정리하고 extrabold는 로고에만. 섹션은 카드를 겹겹이 쌓지 않고
  모바일은 두꺼운 구분 띠, 데스크톱은 얇은 선으로 나눈다.
- 넓은 화면의 예약 상세는 왼쪽(예약 이야기) / 오른쪽 고정(매장·결제·관리) 2단, 모바일 순서는 그대로.

**알림함·아이 기록·필터 (예약 앞뒤를 잇는 화면)**
- 알림함(`/notifications`): 예약 확정·일정 변경·취소, 방문 전날 저녁 6시·당일 아침 안내, 후기 요청, 미용 시기, 곧 끝나는 쿠폰.
  따로 저장하지 않고 예약·아이·쿠폰 상태에서 그때그때 만든다(`lib/notifications.ts`, 단위 테스트). 읽음은 '마지막으로 연 시각' 하나만 저장하고,
  헤더 종 아이콘에 새 알림 수를 보여준다.
- 우리 아이 기록(`/pets/[id]`): 미용 횟수·마지막 미용·다음 추천일, 다가오는 예약, 자주 가는 미용실·미용사에서 같은 조건으로 다시 예약,
  미용 기록 타임라인(요청사항·후기 별점·후기 대기).
- 미용실 필터 시트: 가격대·평점·편의시설(모두 갖춘 곳). 고르는 동안 'n곳 보기'로 결과 수를 바로 보여주고, 0곳이면 적용을 막는다.
  `/salons?q=검색어` 주소로 바로 검색, 헤더 검색 버튼은 검색창으로.
- 예약 내역: 아이별로 보기, 지난 내역 달별 묶음, '후기 n' 대기 표시. 홈에는 후기 대기·쿠폰을 '챙길 일'로 모은다.

**앱처럼 느껴지는 조작**
- 모바일 시트는 손잡이를 아래로 끌어 닫는다(조금 끌면 제자리로). 닫힐 때도 내려가며 사라지고, 알림은 화면 아래에 뜬다.
- 예약 단계는 앞으로 가면 오른쪽에서, 뒤로 가면 왼쪽에서 들어온다.
- 날짜 단계 맨 위 '가장 빠른 예약'을 한 번 누르면 날짜·시간이 함께 정해진다(일정 변경에도 같은 지름길). 달력에는 마감 임박한 날을 점으로 표시.
- 반려동물 사진은 기기에서 가운데를 정사각형으로 잘라 480px JPEG로 줄여 저장한다(원본은 올리지 않음).
  저장된 사진 주소는 앱 경로·이미지 data URL만 받아들이도록 검증한다(`isSafeImage`).
- 미용실 검색의 자주 찾는 검색어·지우기 버튼, 매장 공유(공유 창 또는 링크 복사), 찜 하트·별점 반응.

**예약 이후까지 이어지는 흐름 (V2)**
- 홈은 마케팅 화면이 아니라 **내 상태판**입니다 — 다가오는 예약, 아이별 "예약 있음 / 미용 시기 지남 / 다음 추천일".
- 미용실 상세는 고르는 데 필요한 것만 한 화면에: 고른 서비스 가격, 가장 빠른 예약 시간, 후기 키워드 요약,
  미용사별 전문·가장 빠른 시간, 시설·편의, 이용 전 알아둘 점, 영업시간·휴무. 미용사를 눌러 들어오면 미용실·미용사 단계를 건너뜁니다.
- 지난 이용을 활용합니다 — "지난번과 같은 조건으로", 지난 담당 미용사 우선 표시, 지난 요청사항 자동 불러오기.
- 요청사항은 자주 쓰는 칩 + 짧은 메모. 미용사에게 전달된 내용은 예약 상세에 그대로 남습니다.
- 예약 상세에서 단계별 안내(방문 전 준비물, 픽업 예상 시각), 방문 전날까지 **같은 미용사의 빈 시간으로 일정 변경**·취소,
  `.ics` 캘린더 추가, 길찾기. 이용 완료 후에는 후기(별점+키워드) → 다음 미용 추천일 → 같은 조건으로 재예약.
- 확정 직전에 시간이 막히면 **같은 날 가까운 대안 시간**을 바로 고를 수 있습니다.

**데이터 레이어**
- 저장 데이터를 통째로 믿지 않고 레코드 단위로 검증해, 깨진 항목만 버리고 나머지는 살립니다(`parseStoredDb`).
  JSON이 깨졌거나 다른 모양이면 시드 데이터로 시작합니다.
- 서버 렌더 시에는 빈 상태를 돌려줘 하이드레이션 불일치가 없고, 날짜처럼 브라우저 시각에 의존하는 값은 마운트 후에 그립니다.
- `storage` 이벤트로 다른 탭의 변경을 즉시 반영합니다.
- 데모를 며칠 뒤 다시 열어도 자연스럽도록 시드 예약·쿠폰 기한은 **오늘 기준 상대 날짜**로 만들고, 지난 예정 예약은 이용 완료로 정리합니다.

**접근성 (WCAG 2.1 AA, axe 자동 검사 통과)**
- 색 토큰을 대비 기준(본문 4.5:1)에 맞춰 조정 — 흰 글자 버튼, 보조 글자까지.
- 대화상자: 포커스 가두기, 첫 입력칸 포커스(터치 기기 제외), 닫으면 연 버튼으로 포커스 복귀, Esc 닫기, 입력 중에는 바깥 클릭으로 닫히지 않음.
- 달력: 방향키·Home/End·PageUp/PageDown 이동(roving tabindex), 날짜마다 "10월 9일 금요일, 예약 마감" 같은 이름.
- 본문 바로가기 링크, `aria-current` 내비게이션, 항상 존재하는 live region 토스트, 움직임 줄이기 설정 존중.

**UX**
- 하나만 고르는 단계는 선택 즉시 다음 단계로 넘어가고, 모바일에서는 고른 항목을 한 줄로 보여주며 눌러서 바로 고칠 수 있습니다.
- 미용실 단계에서 **고른 서비스의 미용실별 가격**을 바로 비교합니다.
- 스켈레톤 높이를 실제 카드와 맞춰 레이아웃 흔들림(CLS)을 줄이고, 숫자는 고정폭으로 표시합니다.
- 예약 중 반려동물을 새로 등록하면, 등록 후 그 아이를 선택한 채 예약으로 돌아옵니다.

| `/favorites` · `/my` | 찜한 미용실, 마이페이지(멤버십·쿠폰 상태·알림 설정) |
| `/help` | 이용 안내 — 변경·취소 규정, 쿠폰, 방문 전 준비, 자주 묻는 질문 |

## Supabase 연동 (선택)

MVP는 외부 의존성 없이 동작하지만, 실서비스 전환 시:

1. Supabase 프로젝트 생성 후 `supabase/schema.sql` 실행
2. `lib/db.ts`의 저장·조회 함수를 `@supabase/supabase-js` 호출로 교체 (규칙·검증 로직은 그대로 재사용)

배포 주소가 정해지면 `NEXT_PUBLIC_SITE_URL`을 지정해 공유 미리보기 이미지가 절대 주소로 나가게 합니다.
